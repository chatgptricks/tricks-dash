# Sentient Dash (frontend)

Instagram analytics + content-queue dashboard for Sentient Agency, served at
`sentientdash.app`. React 19 + Vite, single-file-heavy (`src/App.jsx`,
`src/styles.css`) rather than component-per-file — grep is your friend here.

For the full picture (feature set, deploy workflow, backend relationship,
gotchas, backlog) see **`FOR_CODEX.md`** at the repo root. This README only
covers local setup.

## Setup

```bash
pnpm install
pnpm dev
```

React/Vite pages: `index.html` (main dashboard), `queue.html` (Queue board),
and `settings.html` (Admin/Dev command center). Tracker and Insights remain
standalone pages under `public/`. All surfaces read
live data from the `cortex` backend (`chatgptricks/cortex`, deployed on
Render) via `GET /api/dashboard/*`, `/api/tracker/*`, `/api/insights/*`.
Set `VITE_API_BASE` to point at a different backend for local dev.

## Build

```bash
pnpm build
```

Deploying is a two-step, two-branch process (source on `main`, static
output on a separate `gh-pages` branch) — see `FOR_CODEX.md` for the exact
commands and the things that must not be touched on `gh-pages`.

## Smoke test

```bash
node smoke/run.mjs
npm run smoke:queue
npm run smoke:settings
```

Renders the real `<App />` in jsdom with Firebase and `fetch` stubbed, and
asserts the header/filters/favicons actually work. Exists because a past
change shipped a blank page (a TDZ error) that built cleanly and only broke
at render — `vite build` alone doesn't catch that. See `smoke/README.md`
for what it covers.

## Second account: @traselveloreal

@traselveloreal is a second Instagram account shown in Sentient Dash only.
It is **not** part of the shared backend Post DB / API and must never be
written into cortex's data — it's a standalone dataset for this dashboard.

- Canonical DB: `traselveloreal-db/traselveloreal_posts.xlsx` (Posts +
  Summary sheets; no local cover images — cover URLs point directly at
  Instagram's CDN, which can expire over time).
- Bundled frontend data: `src/data/traselveloreal-posts.json` (and
  `traselveloreal-summary.json`), generated by the sync script below and
  imported statically into `App.jsx`. Regenerate and rebuild/redeploy to
  pick up new posts — there's no live API for this account.
- The dashboard merges chatgptricks (from the backend API) with this local
  dataset at runtime and tags every post with `account`. The "Account"
  filter lets you view chatgptricks only, traselveloreal only, or both.

Pull new posts from Apify (`apify/instagram-scraper`, same actor cortex
uses):

```bash
APIFY_TOKEN=xxxx node scripts/sync-traselveloreal.mjs --start --limit 2500
APIFY_TOKEN=xxxx node scripts/sync-traselveloreal.mjs --poll   # repeat until "Done"
```

The run is long (minutes), so it's split into `--start` (kicks off the run,
saves state to `.traselveloreal-sync-state.json`) and `--poll` (checks
status; once `SUCCEEDED`, ingests the dataset — idempotent on shortcode —
and writes both the xlsx and the JSON files the app consumes).

For a cheaper, faster refresh that only looks at recent posts:

```bash
APIFY_TOKEN=xxxx node scripts/sync-traselveloreal.mjs --refresh
APIFY_TOKEN=xxxx node scripts/sync-traselveloreal.mjs --poll   # repeat until "Done"
```

Mirrors cortex's engagement-refresh rule for @chatgptricks: posts 10 days
old or less are refreshed every time; posts 11–29 or 31+ days old are left
alone; posts exactly 30 days old get one final refresh. Any scraped like
count of 3 or below (including Apify's hidden/-1 sentinel) is floored to
500. There's no "Refresh" button for @traselveloreal in the dashboard UI —
this has to be run manually (or scheduled) and the site rebuilt/redeployed
afterward.

## OCR for cover images

Google Cloud Vision OCR at build time. Cached in `outputs/ocr-cache.json`
so reruns only process new/changed covers; text is merged into
`src/data/posts.json` and indexed by search automatically.

```bash
cp .env.example .env
# set GOOGLE_CLOUD_VISION_API_KEY=your_key_here
pnpm ocr:covers
```

Overrides: `OCR_LIMIT=100`, `OCR_FORCE=1`,
`OCR_GOOGLE_PRIMARY_FEATURE=TEXT_DETECTION`,
`OCR_GOOGLE_SECONDARY_FEATURE=DOCUMENT_TEXT_DETECTION`. Uses
`TEXT_DETECTION` first and falls back to `DOCUMENT_TEXT_DETECTION` when the
first result is too short.
